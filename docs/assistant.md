# Отчёты на панели баланса

Нажмите **«Подготовить отчёт»** и введите задание. Период и фильтры с панели баланса видны над полем ввода. В полной конфигурации можно указать другой период прямо в задании. Если модели требуется уточнение, ответьте в том же поле. Исходное задание и ID попытки сохраняются до нажатия **«Новое задание»**.

«Сводка», «Сравнение» и «По базисам» формируют отчёты по готовым сценариям. Календарь «С чем сравнить» появляется в режиме сравнения и предлагает предыдущий период. Панель показывает один текущий результат. Источники содержат применённые фильтры, ссылки на экранные таблицы и идентификаторы запросов. Старый адрес `/balance_comission/analytics` открывает эту панель внутри баланса.

## Запуск на Mac

- `make start` или двойной щелчок по `Запустить.command` запускают панель с доступной моделью.
- `make start-full` загружает настроенную полную модель и запускает обычный режим.
- `make start-experiment` запускает профиль для замеров с точной моделью `qwen3.5:4b-q4_K_M`.

Скрипт запускает Docker Desktop и локальную Ollama из `.runtime/ollama`, PATH или приложения macOS. Он переиспользует существующую базу и загружает `BK.sql` в пустую базу. При первом запуске интернет нужен для загрузки отсутствующих весов и образов. С установленными весами модель работает локально. Ключи хранятся в `.env.analytics`, веса и журналы — в `.runtime`.

Панель доступна по адресу <http://localhost:3000/balance_comission>. `make stop` или `Остановить.command` останавливают сервисы с сохранением данных.

## Как формируется отчёт

- В полной конфигурации инструмент и его параметры выбирает модель. Она может запросить период или другой недостающий параметр. После получения данных модель выбирает факты для пояснения, а приложение строит текст и таблицы из ответа MCP.
- В компактном режиме `qwen3:0.6b` приложение определяет инструмент по готовым правилам и применяет контекст панели. Модель выбирает факты. Для сравнения используйте готовый сценарий «Сравнение» и его календарь.
- Если выбор фактов завершается ошибкой, выводится отчёт по шаблону с отметкой в интерфейсе. Сервис регистрирует причину перехода на шаблон.

Для проверки на демонстрационных данных выберите категорию «Бензин АИ-92» и декабрь 2025 года. В полной конфигурации введите «Сравни распределённый объём за ноябрь и декабрь 2025 года». В отчёте ожидается 657 → 734 тыс. т и изменение +77 тыс. т.

## Замеры

`make start-experiment` проверяет доступность полной модели и сохраняет её контрольную сумму, настройки вывода и версию Ollama в `.runtime/experiment-profile.json`. Используйте один профиль и снимок данных для серии замеров. Для агентной попытки начинайте с поля «Задание» и переносите ID из отчёта или ответа на уточнение в `experiments/measurements.csv`. Укажите условие `agent` или `manual` и время начала и проверки отчёта в ISO 8601 с часовым поясом. В полное время входят ответы на уточнения и исправления. Правильность и полнота отчёта проверяются отдельно.

Журнал сервиса связывает запросы с ID попытки и содержит фактический режим, модель, настройки, вызванные инструменты, число уточнений за запрос и причину перехода на шаблон. Полное время задания рассчитывается по отметкам участника. Серверное время каждого запроса хранится отдельно в `duration_ms`.

```sh
mkdir -p experiments/results
docker compose --env-file .env.analytics -f docker-compose.dev.yaml -f docker-compose.mcp.yaml \
  logs --no-color --no-log-prefix balance_agent > experiments/results/agent-audit.jsonl 2>&1
python3 experiments/reconcile_measurements.py --audit experiments/results/agent-audit.jsonl \
  > experiments/results/measurement-summary.json
```

Сводка считает медианы проверенных ручных и агентных результатов отдельно. Попытки с шаблонным ответом, ошибкой, другим профилем, незавершённым уточнением или непрошедшей проверкой выводятся со своим статусом. Контрольные значения и требования к снимку данных описаны в [документации MCP](mcp.md#контрольные-примеры-и-эксперимент).
